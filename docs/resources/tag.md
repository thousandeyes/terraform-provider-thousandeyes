# thousandeyes_tag (Resource)

This resource manages key/value tags for ThousandEyes assets, including static tags for tests and dashboards and dynamic tags that automatically select Endpoint Agents using filter criteria.

## Example Usage

### Static tag

```terraform
resource "thousandeyes_tag" "example_tag" {
  key         = "Example Tag Key"
  value       = "Example Tag Value"
  object_type = "test"
  color       = "#b3de69"
  access_type = "all"
  icon        = "LABEL"
}
```

### Dynamic Endpoint Agent tag

Dynamic tags select Endpoint Agents automatically when their filter criteria match.
Use `object_type = "endpoint-agent"`, `type = "dynamic"`, a `match_type`, and at
least one `filters` block. `and` requires every filter to match; `or` requires any
filter to match. Filters and their values are unordered.

```terraform
resource "thousandeyes_tag" "endpoint_agents" {
  key         = "office"
  value       = "london-windows"
  access_type = "all"
  object_type = "endpoint-agent"
  type        = "dynamic"
  match_type  = "and"

  filters {
    key    = "platform"
    values = ["Windows"]
    mode   = "in"
    # scope defaults to "default" for built-in ThousandEyes agent fields.
  }

  filters {
    key    = "hostname"
    values = ["LON-*"]
    mode   = "in"
  }
}
```

The filter `scope` identifies where its `key` comes from:

- `default` (the default): a built-in ThousandEyes field, such as `platform`, `hostname`, or `location`.
- `custom`: a user-defined metadata key supplied when an Endpoint Agent checks in, such as `department`.

Filter `mode` is `in` to match one of the supplied values or `not-in` to exclude
all supplied values. Supported keys and value formats are validated by the
[Tags API](https://developer.cisco.com/docs/thousandeyes/v7/taginfo/). The provider
preserves case and wildcards in values.

## Schema

### Optional

- `access_type` (String) [all, partner, system] The access level of the tag. The access level impacts the visibility of the label in UI and the permissions to modify the label.
- `color` (String) Tag color. When omitted, uses the API-provided value.
- `description` (String) The tag's description.
- `filters` (Block Set) Unordered filter criteria for dynamic Endpoint Agent tags. At least one filter is required for dynamic tags. (see [below for nested schema](#nestedblock--filters))
- `icon` (String) Tag icon. When omitted, uses the API-provided value.
- `key` (String) The tags's key.
- `match_type` (String) How dynamic Endpoint Agent tag filters are combined: and requires all filters to match; or requires any filter to match. Required for dynamic tags.
- `object_type` (String) [test, dashboard, endpoint-test, v-agent, endpoint-agent] The object type associated with the tag. Endpoint Agent tags require type = dynamic.
- `type` (String) The nature of the tag: static or dynamic. Only endpoint-agent tags support dynamic assignment. Existing static tags can omit this field.
- `value` (String) The tag's value.

### Read-Only

- `aid` (String) The account group ID.
- `built_in` (Boolean) Indicates whether this is a built-in (system) tag.
- `create_date` (String) Tag creation date.
- `id` (String) The tag ID.
- `legacy_id` (Number) Legacy Id.
- `link` (String) Its value is either a URI [RFC3986] or a URI template [RFC6570].
- `modified_date` (String) The date and time the tag was last modified.

### Nested Schema for `filters`

Required:

- `key` (String) The built-in agent field or custom check-in metadata key to filter on. The API validates supported keys.
- `mode` (String) Whether the agent's value must match a value (in) or must not match any value (not-in).
- `values` (Set of String) Unordered values to match, passed unchanged to the API. Their format and matching semantics depend on the filter key.

Optional:

- `scope` (String) Where the filter key comes from: default for built-in ThousandEyes agent fields, or custom for metadata supplied when an agent checks in.

## Import
In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import) providing `resource_id`.
```terraform
import {
  to = thousandeyes_tag.example_tag
  id = "resource_id"
}
```

Using `terraform import` command.
```shell
terraform import thousandeyes_tag.example_tag resource_id
```
